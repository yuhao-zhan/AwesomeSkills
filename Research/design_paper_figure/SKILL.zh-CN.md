# 学术论文与基金绘图 Skill

## 1. 适用范围

本 Skill 适用于 AI、机器学习、大语言模型、多模态学习、智能体、计算机视觉、自然语言处理、数据挖掘、优化、系统及相关技术方向的学术图。

典型任务包括：

- 研究动机图与问题提出图；
- 总体系统框架图与技术路线图；
- 模型架构图；
- 训练与推理流程图；
- 数据构建、清洗、筛选与标注流程图；
- 检索、工具调用与智能体闭环图；
- Benchmark teaser；
- 方法细节图；
- 实验结果与消融总结图；
- 对既有学术图进行严格局部修改。

目标不是制作装饰性信息图，而是让读者在论文阅读速度下快速理解科学逻辑。

## 2. 核心原则

始终按以下优先级优化：

1. 科学逻辑正确；
2. 数据流与箭头正确；
3. 模块、变量和阶段正确；
4. 最终页面尺度下可读；
5. 视觉层次清楚；
6. 美观。

美观与逻辑冲突时，逻辑优先。

一张优秀的学术图应让读者快速回答：

- 输入是什么？
- 经过了哪些变换？
- 中间表征是什么？
- 最终输出是什么？
- 核心贡献在哪里？
- 训练、推理、监督和反馈如何区分？

## 3. 绘图前先抽象科学结构

写 Prompt 前，先把方法压缩成有向图。

明确：

- 节点：输入、模块、损失、记忆、工具、输出；
- 有向边：数据流、控制流、监督、循环；
- 中间状态：Embedding、Token、隐藏状态、潜变量；
- 最终输出：预测、动作、分数、生成结果；
- 重复结构：层、轮次、阶段、迭代；
- 边界：仅训练、仅推理、外部系统、冻结模块；
- 核心贡献：全图最需要强调的一个机制。

不要从颜色或图标出发，要从依赖关系出发。

## 4. 默认视觉语言

### 4.1 背景与字体

- 默认纯白背景；
- 主文字使用黑色或深灰色；
- 全图使用统一的无衬线字体体系；
- 数学变量使用规范数学记号；
- 使用用户要求的语言，不强制中文或英文；
- 标签尽量使用简短名词短语；
- 避免段落、小脚注式说明和正文复述。

### 4.2 色彩

颜色必须承担语义，而不是装饰。

建议：

- 每种数据类型、模态、分支或阶段使用稳定颜色；
- 普通基础模块使用中性灰；
- 核心贡献使用一种强调色；
- 必要时为结果或决策使用一种结果色。

避免：

- 全蓝色；
- 纯装饰性渐变；
- 大面积浅彩背景板；
- 发光、阴影、玻璃效果；
- 文字、箭头、边框和图标全部同色；
- 使用过多互不相关的颜色。

### 4.3 边框与分组

- 优先通过留白、对齐和细分隔线分组；
- 只有必要时使用浅灰细边框；
- 不要把每个元素都放进圆角矩形；
- 避免卡片嵌套、胶囊标题和 Dashboard 布局；
- 分组边界应表达阶段、范围、归属或训练/推理边界。

### 4.4 科学视觉元素

优先使用技术性表达，而不是通用信息图图标：

- Token 序列；
- Embedding 与特征图；
- 注意力矩阵；
- 时间轴与序列；
- 数据集和样本记录；
- 图结构与记忆库；
- 检索索引；
- Prompt 与生成结果；
- 状态空间轨迹；
- Loss 分支；
- 重复模块；
- 置信度分布；
- 工具调用与环境交互；
- 表格、曲线和结果摘要。

通用图标只有在含义立即明确且技术上准确时才使用。

## 5. 箭头与连线规则

箭头正确性是硬约束。

每条箭头必须具备：

- 唯一起点；
- 唯一终点；
- 真实逻辑含义；
- 明确方向。

禁止：

- 悬空箭头；
- 终点靠近多个模块、含义不明；
- 同一关系重复连线；
- 箭头穿过文字；
- 本应进入子模块却只指向大框边界；
- 可以用短直角线却使用长曲线；
- 不代表计算或控制的装饰性箭头。

视觉层级：

- 最粗：主流程；
- 中等：分支、输出、汇合；
- 最细：监督、残差、循环、辅助信号。

多个信号共同传递时，应先汇总成命名明确的序列、Bundle、Bus 或状态，再连接目标模块。

推荐：

`特征组 -> 评分头 -> 逐项分数 -> 对齐后的分数序列 -> 主干网络`

不推荐：

`多个评分头 -> 多条长曲线 -> 主干内部多个模糊位置`

同一信号作用于多层时，使用一条共享总线加短分支。

## 6. 文字纪律

### 6.1 少而足够

Overview 图通常只保留：

- 阶段标题；
- 模块名称；
- 变量名称；
- 简短输出标签。

细节图可以增加模块名，但仍应避免解释性句子。

尽量用图示代替文字：

- 用错位时间轴表示未对齐；
- 用一一对应的条形表示逐 Token 置信度；
- 用检索闭环表示重复搜索；
- 用轨迹或 Token 流表示迭代生成。

### 6.2 文字白名单

当生图模型容易生成错字时，明确列出允许出现的标签，并禁止自行生成其他文字。

### 6.3 正式排版文字

当文字必须完全准确时：

1. 先生成少字或占位符版本的视觉骨架；
2. 在 PowerPoint、Figma、Illustrator、Inkscape 或 LaTeX 中手工替换文字；
3. 导出 SVG/PDF 或高清 PNG。

不要依赖生图模型生成密集且完全准确的正式文字。

## 7. 布局原则

### 7.1 几何先于装饰

Prompt 中应使用几何描述：

- 左 / 中 / 右区域；
- 上下平行流；
- 行对齐；
- 固定分支点；
- 精确模块顺序；
- 中间变量的内外位置；
- 线进入大组还是具体子模块。

弱指令：

“让架构更清楚。”

强指令：

“Token 序列放在上方，评分序列放在下方；两者左端对齐、长度一致，并水平输入主干。评分序列只进入注意力模块。”

### 7.2 总览图

建议：

- 一条主导的左到右或上到下流程；
- 3–6 个主要阶段；
- 内部细节有限；
- 核心贡献是视觉中心；
- 必要时只有一个清晰反馈或迭代闭环。

已有专门细节图时，不要在 Overview 中重复展开底层结构。

### 7.3 细节图

应体现：

- 精确模块顺序；
- 精确分支点和汇合点；
- 清楚的残差、循环或监督路径；
- 一个完整重复模块加 `x L`、层叠轮廓或迭代标记；
- 最少的上下游背景。

细节图只解释一个机制，不承载整篇论文。

### 7.4 训练与推理

如果同时出现，使用以下方式明确区分：

- 上下两条 lane；
- 实线 / 虚线边界；
- 不同箭头样式；
- 清晰阶段标题。

不要把训练损失、标签和推理输出混在同一条无差别流程中。

## 8. 变量与表征的位置

变量位置必须反映语义角色。

- 输入变量位于消费它的模块之前；
- 中间表征位于模块内部或其实际产生位置；
- 最终输出位于产生模块之外；
- Loss 与监督信号使用独立细支路；
- 跨步骤持续存在的缓存、记忆或状态应画在循环中持续保留的位置。

示例：

若 `Z` 是主干内部共享表征，应放在主干内部、靠近产生它的阶段。主干边界直接连接下游任务头。除非方法明确把 `Z` 作为可交付输出，否则不要把它单独画成外部输出框。

若 `R` 是逐 Token 分数序列，应先画：

`Token -> 评分头 -> 逐 Token 分数 -> 对齐后的序列 R`

再通过一条清晰路径输入实际使用它的模块。

## 9. 重复与迭代结构

对于重复层：

- 完整展开一个代表性 Block；
- 使用 `x L`、叠放轮廓或大括号表示重复；
- 共享辅助输入使用总线；
- 除非每层不同，否则不要把所有层完全展开。

对于推理迭代、Agent Loop 或 Refinement：

- 明确循环入口和出口；
- 区分持久状态与新生成状态；
- 区分模型调用与工具/环境调用；
- 只有当停止条件是方法核心时才画出停止条件。

## 10. 常见图型

### 10.1 研究动机 / 问题图

使用问题递进，而不是卡片看板。

典型结构：

`现有设置 -> 失败机制 -> 后果 -> 研究目标`

可通过冲突证据、上下文缺失、噪声监督、分布偏移、幻觉、长上下文过载或决策不确定性表现失败。

### 10.2 总体系统 / 技术路线图

覆盖所有主要研究内容，但细节分配不均：

- 上游足够展示输入如何形成表征；
- 中间足够展示核心机制；
- 下游足够展示输出、评估或反馈；
- 已有单独细节图的部分不重复展开。

### 10.3 模型架构图

使用明确数据流：

`输入 -> 编码器 -> 对齐表征 -> 主干 -> 任务头 -> 输出`

只有在相关时才标注冻结、共享、可训练或外部模块。

### 10.4 数据与训练流程图

典型结构：

`原始来源 -> 清洗/筛选 -> 标注或合成 -> 训练混合 -> 目标函数 -> 模型`

标签、负例、奖励和偏好对使用独立路径。

### 10.5 检索、工具调用与智能体系统

典型结构：

`查询 -> 规划器/模型 -> 检索或工具调用 -> 观察 -> 状态更新 -> 最终输出`

重复交互只使用一个清晰循环，避免大量回流箭头。

### 10.6 Benchmark Teaser

使用受控对比：

`原始设置 -> 挑战或变化 -> 方法响应 -> 结果`

各阶段保持相机、布局、尺度或样本结构一致，只改变目标因素。

统计信息使用一条简洁信息带，不使用多个 Dashboard 卡片。

### 10.7 方法细节图

精确解释一个机制。

Transformer 类模块可展开：

`输入 -> 投影 -> 改进注意力 -> Add & Norm -> FFN -> Add & Norm -> 输出`

除非公式本身就是贡献，否则公式应退居辅助位置。

### 10.8 评估与消融图

优先使用曲线、柱状图、散点图或结构化比较，不使用装饰图标。

- 基线与变体对齐；
- 每个 Panel 只突出一个结论；
- 坐标轴与单位明确；
- 除非为了可访问性，不要用颜色、形状和文字重复编码同一信息。

### 10.9 严格局部修改

修改既有图时：

- 明确允许修改的区域；
- 列出所有必须保持不变的元素；
- 说明是复制替换、重绘、换色还是改字；
- 禁止修改目标区域外内容。

需要像素级一致复制时，应使用图形编辑或合成流程，而不是生成式重绘。

## 11. Prompt 编写流程

写 Prompt 前先确定：

1. 图型；
2. 一句话科学信息；
3. 模块和箭头组成的图；
4. 输入、中间变量与最终输出；
5. 要强调的贡献；
6. 当前图适合的细节层级；
7. 允许出现的文字；
8. 语义配色；
9. 精确几何布局；
10. 禁止出现的内容和已知失败模式。

Prompt 按以下顺序写：

### A. 任务与目的

说明图型和科学信息。

### B. 范围

说明包含与排除内容。

### C. 硬约束

明确：

- 箭头；
- 变量位置；
- 文字数量；
- 语言；
- 分辨率；
- 风格限制。

### D. 精确布局

定义区域、行、序列对齐、分支点、汇合点和循环。

### E. 模块内容

只描述每阶段必要的视觉组件。

### F. 文字白名单

需要准确文字时列出允许标签。

### G. 负面限制

明确禁止错误结构、无关模块、错误文字、UI 风格和歧义箭头。

## 12. 通用 Prompt 模板

```text
请创建一张适用于[论文 / 基金 / 技术报告]的出版级学术图。
图型：[总览 / 模型架构 / 方法细节 / 数据流程 / Benchmark teaser / 动机图 / 评估图 / 局部修改]。
科学信息：[一句话说明]。

硬约束：
- 科学逻辑与箭头正确性优先于美观。
- 每条箭头只有一个明确起点和终点。
- 禁止悬空、重复、交叉和装饰性箭头。
- 使用白底、深色文字、细中性边框和有限语义配色。
- 禁止 Dashboard 卡片、大面积浅彩背景、渐变、阴影、发光和全蓝风格。
- 尽量少字，优先用序列、矩阵、图结构、时间轴、轨迹、曲线和模块结构表达。
- 使用最高可用分辨率和清晰矢量风格。

范围：
- 包含：[内容]。
- 排除：[内容]。

布局：
- [定义左 / 中 / 右或上 / 下几何结构。]
- [定义行对齐、平行流、分支、汇合和反馈回路。]

流程：
[输入] -> [变换1] -> [变换2] -> [输出]。

变量位置：
- [输入变量] 位于 [模块] 之前。
- [中间变量] 位于 [模块] 内部的 [具体阶段]。
- [最终输出] 位于 [模块] 外部。

模块细节：
[只描述必要模块及顺序。]

文字：
只允许以下标签：
[白名单]
禁止自行生成其他文字。

负面限制：
[禁止错误结构、无关模块、文字堆积、歧义箭头、错误文字和 UI 元素。]
```

## 13. 迭代策略

复杂图不要一次同时解决结构与美化。

推荐顺序：

1. 结构草图；
2. 科学逻辑与箭头检查；
3. 变量位置检查；
4. 删字；
5. 视觉风格；
6. 高清导出；
7. 手工字体清理。

当多次修改仍保留错误布局时，不要继续说“优化”。应明确：

- 删除目标区域；
- 按指定几何结构重画；
- 禁止复用旧内部布局。

## 14. 质量检查清单

### 科学正确性

- 每个模块是否对应正文方法？
- 训练、推理、评估是否正确区分？
- 中间表征与最终输出是否区分？
- 是否还残留已删除或过时内容？

### 箭头

- 每条箭头能否用一句话解释？
- 是否进入准确子模块？
- 是否有交叉、悬空或方向反转？
- 辅助信号是否弱于主流程？

### 布局

- 缩略图尺度下能否看出主线？
- 核心贡献是否是视觉中心？
- 重复元素是否对齐？
- 平行序列是否平行且需要时一一对应？
- 分支与汇合点是否几何清楚？

### 文字

- 是否还能删掉标签而不损失逻辑？
- 是否无必要地复述正文？
- 是否出现错字、伪字或自造短语？
- 最小文字在最终页面是否可读？

### 风格

- 是否更像论文图，而不是商业信息图？
- 颜色是否有限且有语义？
- 边框与填充是否克制？
- 背景是否以白色为主？

### 导出

- 是否足够高清？
- 放大后文字与箭头是否锐利？
- 是否可以转成或重绘为 SVG/PDF？

## 15. 常见失败与修复

### AI 味过重

原因：

- 全蓝色；
- 大面积浅彩面板；
- 圆角卡片布局；
- 通用图标过多；
- 所有区域视觉权重相同；
- 解释文字太多。

修复：

- 回到白底黑字；
- 颜色只表达语义；
- 删除背景面板；
- 用技术性视觉元素替代通用图标；
- 删标签；
- 强化一条主流程。

### 修改后箭头仍错误

原因：

- Prompt 只说“箭头更清晰”，没有定义几何关系。

修复：

- 明确起点、终点、路径和禁止目标；
- 使用对齐行与共享总线；
- 删除长曲线；
- 重画目标区域而不是修补。

### 中间变量看起来像最终输出

原因：

- 变量放在模块边界外。

修复：

- 把变量放进实际产生它的内部阶段；
- 模块边界直接连接下游任务头。

### 辅助评分路径混乱

原因：

- 多条分散支路直接接入主干。

修复：

- 先生成逐项值；
- 对齐或拼接成一个序列；
- 通过一条清晰输入路径送入主干。

### 架构框只是术语列表

原因：

- 在方框内堆标签，没有内部数据流。

修复：

- 改成有顺序的内部模块与箭头；
- 标出中间表征产生位置；
- 每个阶段使用一个明确视觉元素。

### 修改几乎没有变化

原因：
